## 1. 方案总览

### 1.1 系统上下文

```
┌─────────────────────────┐
│  super-portal-admin SPA │
│  (React 19 + Vite 8)    │
│  部署：/portal/admin/    │
└───────────┬─────────────┘
            │ 同域网关（无跨域）
   ┌────────┴────────────────────────┐
   │                                 │
   ▼ /superentry-uat/**              ▼ /superentry-node-uat/**
┌──────────────────┐        ┌──────────────────────┐
│ Java 服务         │        │ Node 服务 (NestJS)    │
│ UA-HiAgent-Plugin│        │ UA-HiAgent-Plugin     │
│                  │        │                      │
│ GET /api/auth/   │        │ POST /assets/import-knowledge │
│     lark/me      │        │ POST /assets/clear-knowledge  │
│ GET /api/auth/   │        │ POST /assets/import-table     │
│     lark/user    │        │ GET /assets   DEL /assets/:id │
│     lark/user    │        │ GET/POST/PATCH/DELETE│
│ (Bearer 会话校验) │        │      /whitelist      │
│                  │        │ GET/POST/PATCH/DELETE│
│                  │        │      /skill-mapping  │
└──────────────────┘        │ (x-api-key 鉴权)     │
                            └──────────────────────┘
```

### 1.2 复用清单（本方案不写任何后端代码）

| 复用项 | 来源 | 说明 |
| --- | --- | --- |
| `GET /api/auth/lark/me` | Java 服务 | 登录验证，`Authorization: Bearer <sessionId>`，HTTP 401 + errorCode "402" 表示会话失效 |
| `GET /api/auth/lark/user` | Java 服务 | 用户档案查询（openId/用户名/邮箱三选一，读登录落库档案不实时调 Lark；查无档案 errorCode B0100） |
| `POST /assets/import-knowledge` | Node 服务 | 知识库资产同步（product-* → assets upsert），幂等，同步长耗时 |
| `POST /assets/clear-knowledge` | Node 服务 | 清空知识库导入的资产（物理删除 product-* 行，v1.3 补录），幂等，同步长耗时 |
| `POST /assets/import-table` | Node 服务 | 商品属性同步（HiAgent 数据库表按 SKU 回填 gender/des），幂等，同步长耗时 |
| `GET /assets` | Node 服务 | 资产分页查询（DatasetId/Keywords，仅 active=1，v1.3 起查询卡片使用）；另以 `PageNumber=1&PageSize=1` 取 total 展示 |
| `DELETE /assets/:id` | Node 服务 | 删除单条资产（物理删除，返回被删快照；404 ASSETS_NOT_FOUND） |
| `GET /POST/PATCH/DELETE /whitelist` | Node 服务 | 白名单 CRUD（DELETE 为 query 传参；PATCH 仅 remark） |
| `GET/POST /skill-mapping` + `PATCH/DELETE /skill-mapping/:id` | Node 服务 | skill 映射 CRUD（POST 单条无批量；PATCH 仅人工字段 nameCn/module/status/desc/input/output/remark；DELETE 路径参数物理删除） |
| 工程范式 | super-portal | vite 配置、双后端 axios 封装、shadcn 组件（@base-ui/react 底座）、env 分层、构建脚本 |
| UI 组件 | super-portal `src/components/ui/` | 直接拷贝 button / select / popover；其余按同范式补写 |

### 1.3 明确不引入

- 不引入状态库（redux/zustand）与数据请求库（react-query），对齐 super-portal 的自定义 hooks 范式；
- 不引入 super-portal 中的富文本（tiptap）、markdown、vconsole 等无关依赖；
- 不做 mock 层（接口均已存在于 UAT，dev 直连 UAT 联调）。

## 5. 请求层设计（核心）

### 5.1 单实例 + 按 url 前缀路由双后端

`src/services/request.ts`，机制照搬 super-portal 的 `request.ts`，差异点：无 SSE、无静默重登（admin 的会话失效直接踢回登录页）。

```ts
const http = axios.create({ baseURL: API_BASE_URL, timeout: 15_000 })

http.interceptors.request.use((config) => {
  if (config.url?.startsWith(SUPERENTRY_API_PREFIX)) {
    // Java 接口：切换 baseURL + 注入 Bearer sessionId
    config.baseURL = SUPERENTRY_API_BASE_URL
    const sessionId = getSessionId()
    if (sessionId) config.headers.set(HEADER_AUTHORIZATION, `Bearer ${sessionId}`)
  } else {
    // Node 接口：注入 x-api-key
    config.headers.set(HEADER_X_API_KEY, X_API_KEY)
  }
  return config
})
```

### 5.2 响应拦截：统一解包 + 统一 ApiError

```ts
export class ApiError extends Error {
  constructor(
    message: string,
    public readonly source: 'java' | 'node',
    public readonly status?: number,       // HTTP 状态码
    public readonly errorCode?: string,    // Node: WHITELIST_DUPLICATE...；Java: "402"...
  ) { super(message) }
}
```

拦截器逻辑（无论 HTTP 错误还是 HTTP 200 但 success=false，都收敛为 reject ApiError）：

1. **HTTP 层错误**（axios error）：
   - Java 源 + status 401 → 清凭证 → `window.location` 跳 `/login` + toast「登录已失效，请重新登录」（用整页跳转而非 navigate，确保所有页面状态重置）；
   - Node 源 + status 401 → `ApiError('服务鉴权失败（x-api-key），请联系开发')`；
   - 其余 → 透传 status + 后端 errorMessage。
2. **HTTP 200 但 `success !== true`**：抛 `ApiError`（带 errorCode/errorMessage）。后端 Nest 的 HttpCustomException（409/404 等）走的就是这条路径，status 从 `error.response.status` 取。

成功路径直接 `return envelope.data`——**hooks 拿到的即业务数据**，不再判 success。

### 5.3 超时策略

## 7. 关键设计细节

### 7.1 sessionStorage key 冲突规避（重要）

admin 与 super-portal 可能部署在**同源**（如 `hiagent-plugin.underarmour.cn/portal/uat/` 与 `/portal/admin/`），而 sessionStorage 按 origin 共享、不区分路径。因此 admin 的 key 必须用**独立前缀**，避免覆盖 super-portal 的会话（key `super-portal:super-entry-session`）：

```ts
// constants/storage.ts
export const STORAGE_KEY_ADMIN_SESSION = 'super-portal-admin:session-id'
export const STORAGE_KEY_ADMIN_USER = 'super-portal-admin:user'
```

### 7.2 列表竞态守卫

翻页/切换筛选时慢响应后到会污染页面，`useWhitelistList` 内用序号守卫：

```ts
const seqRef = useRef(0)
const load = useCallback(async (params) => {
  const seq = ++seqRef.current
  setLoading(true)
  try {
    const data = await fetchWhitelist(params)
    if (seq === seqRef.current) setData(data)   // 仅最后一次请求可落地
  } finally {
    if (seq === seqRef.current) setLoading(false)
  }
}, [])
```

### 7.3 白名单「当前页 openId 搜索」实现

后端不支持 openId 过滤（PRD Q2），V1 前端实现：`items.filter(i => i.openId.includes(keyword))`（useMemo），输入框 placeholder 明示「仅搜索当前页」，并在下方 caption 提示「跨页搜索需后端支持（V2）」。空结果时 EmptyState 文案区分「筛选无结果，试试清除搜索或切换筛选」。

### 7.4 同步状态机（useMigration，两卡片各自独立一份）

```
idle ──点击「开始同步」──▶ confirming（ConfirmDialog）
confirming ──取消──▶ idle
confirming ──确认──▶ importing（本卡片按钮 loading+禁用，另一卡片不受影响）
importing ──成功──▶ success（结果统计卡 + 资产总数刷新）
importing ──失败──▶ failed（卡片内错误 + 重试入口；接口幂等，重试安全）
success/failed ──「再次同步」/「重试」──▶ confirming
```

三个操作（useKnowledgeImport / useKnowledgeClear / useTableImport）各自持有独立状态机实例——清空复用同一状态机（importing 语义为清空进行中；useKnowledgeClear 为已实现代码的 v1.3 补录）；useAssetsTotal 供给页面标题区的资产总数，初始加载 + 任一同步/清空/删除成功后刷新（失败静默为 null）。

确认弹窗文案（利用幂等性降低顾虑，两卡片覆盖策略不同需分开说明）：
> 知识库同步：将从知识库 product-\* 数据集同步资产图片数据到 UAT 资产库。按 docId 幂等 upsert，重复执行不会产生重复数据；不会覆盖已人工设置的年份/季节/可见性。
>
> 属性同步：将从 HiAgent 数据库表按 SKU 匹配回填性别线（gender）与款名（des）。匹配即覆盖（HiAgent 表为事实源），幂等可重复执行；不会影响资产图片数据。

### 7.5 表单校验规则（前端第一道，与后端 DTO 对齐）

| 字段 | 规则 | 错误文案 |
| --- | --- | --- |
| openId | 必填、去首尾空格、≤128 | 「openId 不能为空」/「openId 最长 128 字符」 |
| feature | 必选枚举 | 「请选择权限点」 |
| remark | ≤512，默认预填 `操作人：${name}` | 「备注最长 512 字符」 |

后端 409（`WHITELIST_DUPLICATE`）→ 表单不关闭，openId 字段下提示「该用户已拥有此权限点」；404（`WHITELIST_NOT_FOUND`，编辑/删除并发冲突）→ toast「记录不存在（可能已被其他管理员操作）」+ 列表 refetch。

### 7.6 错误码 → UI 行为映射（集中收敛）

| 来源 | status / errorCode | UI 行为 |
| --- | --- | --- |
| Java | 401 / "402" | 清凭证 → 跳 /login + toast |
| Node | 401 | toast「服务鉴权失败，请联系开发」 |
| Node | 400 参数错误 | 表单就地提示 |
| Node | 404 / `*_NOT_FOUND` | toast + 列表 refetch |
| Node | 409 / `WHITELIST_DUPLICATE` | 表单字段级提示 |
| Node | 409 / `SKILL_MAPPING_DUPLICATE` | 弹窗归集提示，保留失败行重试 |
| Node | 5xx / `ASSETS_IMPORT_FAILED` | toast（含 errorMessage）+ 可重试 |
| 网络 | ECONNABORTED 等 | ErrorState 组件 + 重试按钮 |

### 7.7 skill 批量新增的分组提交（并发限流，v1.1 新增）

后端 `POST /skill-mapping` 仅单条（skillId 唯一 409）。多行表单一次提交时**不能** `Promise.all` 全量并发（几十条同时打后端 = 请求风暴），也不能纯串行（慢）。采用**分组限流**：`CREATE_CHUNK_SIZE=5` 条一组，组内并发、组间 `await` 串行，瞬时并发压在常数级；行数上限 `CREATE_MAX_ROWS=20` 防误操作。

```ts
// useSkillMappingMutations.createMany
const chunks = []                              // 切组
for (let i = 0; i < payloads.length; i += CREATE_CHUNK_SIZE) chunks.push(payloads.slice(i, i + CREATE_CHUNK_SIZE))
let done = 0
for (const chunk of chunks) {                  // 组间串行
  await Promise.all(chunk.map(async (payload) => {   // 组内并发
    try { await createSkillMapping(payload); result.succeeded.push(payload) }
    catch (e) {
      if (e instanceof ApiError && e.status === 409) result.duplicates.push(payload)
      else result.failed.push({ payload, message: ... })
    } finally { setProgress({ done: ++done, total: payloads.length }) }   // 弹窗展示「提交中 done/total」
  }))
}
if (result.succeeded.length > 0) onChanged()   // 有成功才刷新列表
return result                                  // 不抛出，弹窗按 succeeded/duplicates/failed 分层提示
```

配套交互：弹窗内 skillId 去重（同批重复必 409，提交前就地拦截）；部分失败时弹窗保留、仅保留 duplicates+failed 对应的行便于修正重试；与白名单 `createMany` 的差异即在此——白名单仅 3 个权限点全量并发可接受，skill 上限 20 条必须限流。

### 7.8 弹窗高度与内部滚动（v1.1 新增）

`DialogContent` 默认无 max-height：字段多的编辑弹窗（7 个可改字段）在 720p 视口下底部按钮会被截到屏幕外且 fixed 定位无法滚动到达。skill 的两个弹窗统一 `max-h-[85vh] overflow-y-auto thin-scroll`；新增弹窗多行列表区另加 `max-h-72` 内部滚动（§8.4）。存量 whitelist 弹窗字段少未受影响，暂不动。

### 7.9 资产查询与删除卡片（v1.3 新增）

/migration 页第三张卡片（`AssetQueryCard` + `AssetQueryTable`，hooks 在 `useAssetsQuery.ts`），复用既有 `GET /assets` / `DELETE /assets/:id`：

- **显式提交查询**：DatasetId 为**固定下拉框**（PRD v1.6：「全部数据集」+ product-shoes/bag/hat/pants/outerwear/top 六个别名，选中「全部数据集」时不传 DatasetId，等价原留空查全部）；Keywords 仍为文本输入，逐键触发会形成请求风暴，故统一由「查询」按钮/回车提交（`useAssetsQuery.setQuery`，页码重置 1、输入 trim、空串归一为 undefined）。与 skill/whitelist 的「下拉即查」不同，这里既不防抖也不输入即查（两个项目此前「不做防抖」的决策均针对前端当前页过滤的无请求开销场景，不适用服务端查询）；
- **首次进入不自动请求**：`started=false` 时展示引导空态——这是一张按需使用的工具卡片而非主列表页，进页面就拉全量第一页没有消费方；
- **竞态守卫同构 useSkillMappingList**：自增序号 + cancelled 标记，查询/翻页/页大小/重新查询四入口共享；
- **删除走 useAssetRemoval**：行级 `removingId` loading；404（ASSETS_NOT_FOUND）视为并发删除冲突 → toast「资产不存在（可能已被删除）」+ 列表刷新 + 关弹窗，其余异常 toast errorMessage 由调用方处理；成功后 `list.refetch()` + `onAssetsChanged`（MigrationPage 的 `refresh`）联动页头 total；
- **口径陷阱需文案兜底**：`GET /assets` 仅返回 active=1——主站「隐藏」的商品同样查不到，「查询不到」≠「已删除」。卡片说明与删除确认 hint 均明示「隐藏 ≠ 删除，以删除接口结果为准」；
- 表格列：ID/SKU 复用 CopyableText（便于与接口/日志比对），文件名/款名截断 + hover 全文；关键词输入框 `maxLength=128` 与后端 DTO 对齐。

## 10. 自测清单（对应 PRD BDD 逐条验证）

**登录**：有效 sessionId 通过；unionId/name 缺失拒绝；无效/过期 sessionId 401 拒绝；刷新保持登录；退出清凭证；登录页直接访问 /migration 被重定向。

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| **网关层超时先于 axios 300s**（Nginx/网关常见 60s 截断长请求） | 同步数据量大时网关直接断连，前端拿到的是网络错误而非业务结果 | M5 联调时用真实数据量实测两个同步接口端到端耗时；若被网关截断：V1 文案提示「同步可能仍在后台执行，结果可通过再次同步（幂等）或资产总数确认」，V2 推动后端异步化（PRD Q3） |
| x-api-key 硬编码前端包内 | 知道 key 的任何人都可直接调 Node 接口（与 super-portal 现状一致，非本项目新增风险） | 已知风险接受；V2 随 admin_console 权限点方案一并收敛（PRD Q1） |
| 任何有效 sessionId 均可进入 admin | 非管理员可改白名单 | V1 内部地址管控；登录有效口径已含 unionId+name 双字段，操作人可追溯（PRD Q1/Q7） |
| 同源 sessionStorage key 冲突 | 覆盖 super-portal 会话导致用户端掉线 | admin 专属前缀 key（§7.1），联调时验证 |
| DELETE query 传参中 openId 含特殊字符 | 删除失败 | axios params 自动 encode，自测覆盖含 `+`/`/` 的 openId 样本 |
